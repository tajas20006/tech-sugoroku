# MVP ゲーム仕様

## 目的

2人が同じ画面で遊び、AWS の基本知識をクイズで学びながら、クレジットを管理してゴールを目指す。

## アーキテクチャ要件

- ゲーム進行を中心ドメインとし、Flet やファイルシステムに依存しない `techsugoroku.domain` に置く。
- `Game` を対戦セッションの集約ルートとし、プレイヤー、ターン、未回答クイズ、勝者の整合性を一括して管理する。
- 盤面配置と支払日を不変なドメイン設定として `Board` に集約し、位置判定を UI から分離する。
- クレジットの下限、アイテム所持上限、アイテム消費などの不変条件は `Player` のドメイン操作を経由して保つ。
- ユースケースの生成と外部データ取得の境界は `techsugoroku.application` に置き、クイズ取得をポートとして表現する。
- Markdown の解析とファイル読み込みは `techsugoroku.infrastructure` に置き、ドメイン層から分離する。
- `main.py` はプレゼンテーション層として、アプリケーション層が構築したゲームを操作する。ゲームルールを重複させない。
- 既存利用者向けの `game.py` 公開 API は互換ファサードとして維持する。
- ランダム処理は `random.Random` を注入でき、テストで再現可能にする。
- 依存方向は `presentation -> application -> domain` および `infrastructure -> application/domain` とし、`domain` は外側の層へ依存しない。

### DDD 化の受け入れ条件

1. `techsugoroku.domain` は Flet とファイル I/O に依存しない。
2. Markdown クイズリポジトリを差し替えてゲームを生成できる。
3. 盤面、支払日、クレジット、所持品の不変条件がドメイン単体テストで検証される。
4. 従来の `from game import Game, Item, Question, SpaceType, load_questions` が引き続き利用できる。
5. 既存のゲームルールと GUI 演出に回帰がなく、全検証コマンドが成功する。

## 画面要件

- 60マスの2D盤面を表示する。背景は `assets/images/board-background.png` を使用する。
- 左側に各プレイヤーの位置、クレジット、所持アイテムを表示する。
- 右側に「サイコロを振る」ボタン、イベントログ、クイズの選択肢を表示する。
- プレイヤーは青とピンクのトークンで区別する。

## ルール要件

- 2人の初期クレジットは 300、初期位置は 0、青プレイヤーから開始する。
- サイコロは 1〜6。プレイヤーは出目の数だけ進み、ゴールを超えた位置は 59 に丸める。
- マス種別は `gain`、`loss`、`quiz`、`payment`、`item`、`summit`、`exam`、`goal`。
- `gain` はクレジット +100、`loss` は -40（0未満にはしない）。
- `quiz` は4択。正解なら +100、不正解なら -20。回答後にターン終了。
- `exam` は4択。正解なら +300 と認定バッジ、不正解なら -80。
- `payment` を通過または停止すると、必要クレジットを判定する。足りれば支払い、足りなければ直前の支払日へ戻す。
- 支払日は位置 15（100）、30（180）、45（280）、55（400）。位置 15 の不足時は START に戻す。
- `item` は「追加アイテム仕様」を含む候補からランダムに1個を得る。所持上限は3個。
- 能動アイテムはサイコロ前に1ターンにつき1個だけ使える。Auto Scaling と CloudFront は次のサイコロに +2 する。
- WAF、AWS Backup、Multi-AZ は自動防御アイテムであり、対応する攻撃またはコスト発生時に1回だけ消費される。
- `summit` はランダムイベント。クレジット +100、アイテム獲得、または DDoS（WAF がなければ -100）のいずれか。
- 最終支払日を通過済みのプレイヤーがゴールへ到達すると勝利する。

## MVP の盤面

マスの大半は通常マスとし、イベントを以下に固定配置する。

| 位置 | 種別 |
| ---: | --- |

| 6, 18, 26, 42, 52 | loss |
| 5, 8, 13, 17, 22, 27, 35, 39, 44, 50, 53, 57 | quiz |

| 2, 10, 16, 24, 32, 37, 47, 51, 56 | item |

| 59 | goal |

## 受け入れ条件

1. サイコロを振ると現在プレイヤーだけが進み、イベント解決後にターンが交代する。
2. クイズと資格試験は、回答されるまでターンを交代しない。
3. クレジットは常に0以上で、支払不足時は指定通り戻る。
4. WAF、AWS Backup、Auto Scaling の効果が一度だけ正しく適用される。
5. 最終支払日を通過済みのプレイヤーだけがゴールで勝利できる。
6. 質問は `assets/quiz.md` と `assets/quiz-architecture.md` から読み込み、同じカテゴリの質問を使い切るまで再出題しない。
7. サイコロを振ると出目の切り替え、拡大・縮小、最終出目の強調を表示してから移動する。
8. トークンは出目の数だけ1マスずつ移動し、各マスで短くバウンドする。
9. イベント結果は画面上部のバナーで色とアイコンを伴って表示する。
10. 支払日を通過または停止した時、および資格試験、AWS Summit、アイテム、クイズ、コスト発生では、盤面を覆う短いカットインを表示する。
11. 盤面は全体を常に表示せず、現在ターンのプレイヤー周辺を拡大した追従カメラで表示する。
12. マスは直交グリッドではなく、半径が変化する円環状のコースに不規則に配置する。
13. 隣接マス同士は重ならない最小間隔を保つ。
14. 開始前は全コースを俯瞰表示し、STARTボタンを押すと現在プレイヤー周辺へカメラを寄せてゲームを開始する。
15. サイコロ演出を始める前に、カメラは必ず現在ターンのプレイヤートークンを追跡する。
16. 現在ターンのプレイヤーは、サイコロ前に所持する能動アイテムを使用できる。2人対戦の妨害アイテムは自動的に相手プレイヤーを対象にする。
17. 通常ターン終了後は、イベント演出の完了後に次ターンのプレイヤートークンへカメラを移す。
18. 所持アイテムにはホバーで効果と使用タイミングを示すツールチップを表示する。
19. 開始画面のSTARTボタンの下に「遊び方」ボタンを置き、サイコロ、移動、支払日、アイテムをビジュアル付きで説明する。
20. クレジット獲得、コスト発生、支払日、AWS Summit、アイテム取得の表示メッセージは、イベントごとに複数候補からランダムに選ぶ。

## 追加アイテム仕様

| アイテム | 分類 | 効果 |
| --- | --- | --- |
| リザーブドインスタンス | 自己強化 | 使用後、次のコスト発生を半減する。 |
| Cost Explorer | 自己強化 | 使用後、次の支払日を 50 Credits 軽減する。 |
| Well-Architected Review | 自己強化 | 使用後、次のクイズで不正解の選択肢を1つ隠す。 |
| AWS サポートプラン | 自己強化 | 使用後、次に失敗したクイズのペナルティを無効化する。 |
| Transit Gateway | 進行補助 | 使用後、次のサイコロに +3 する。MVPではショートカットとして扱う。 |
| Lambda | 進行補助 | 使用後、次のターンを追加で得る。 |
| DDoS 攻撃 | 妨害 | 相手の WAF がなければ、相手のクレジットを 100 減らす。 |
| 不要な NAT Gateway | 妨害 | 相手のクレジットを 60 減らす。 |
| 無限 CloudWatch Logs | 妨害 | 相手が次に得るクレジットを半減する。 |
| リージョン障害のうわさ | 妨害 | 相手を1ターン休みにする。Multi-AZ で防げる。 |
| Multi-AZ | 防御 | リージョン障害のうわさを1回無効化する。 |

### 追加受け入れ条件

1. 追加アイテムはアイテムマスと AWS Summit のランダム獲得候補に含まれる。
2. 能動アイテムは現在ターンのプレイヤーカードから使用でき、説明ツールチップを持つ。
3. 自動防御アイテムは攻撃／コスト発生時に自動消費される。
4. クレジットは追加アイテムの効果後も0未満にならない。
5. 1ターンに能動アイテムを2個以上使えない。
6. Well-Architected Review、AWS サポートプラン、無限 CloudWatch Logs の「次回」効果は、対象イベントで1回だけ消費される。
