# 実装・テスト計画

## タスク分割

1. `game.py` に状態と純粋なルールを実装する。
2. `tests/test_game.py` に、移動・クレジット・支払日・クイズ・アイテム・勝利のテストを作る。
3. `main.py` に盤面、プレイヤー情報、操作、クイズモーダルを実装する。
4. pytest、ruff、Flet 起動確認を実行する。

## テストシナリオ

| シナリオ | 入力 | 期待結果 |
| --- | --- | --- |
| 通常移動 | 青が3を振る | 青が位置3、gainでクレジット280、ピンクのターン |
| クレジット下限 | 0クレジットでloss | クレジット0 |
| 支払成功 | 位置14、200クレジット、出目1 | 位置15、50クレジット |
| 支払失敗 | 位置14、100クレジット、出目1 | 位置0、100クレジット |
| クイズ | quizマスに停止して正解 | +80後、ターン交代 |
| WAF | WAF所持中にDDoS | クレジット不変、WAF消費 |
| Auto Scaling | Auto Scaling所持中に出目4 | 6マス進む、アイテム消費 |
| 勝利 | 最終支払済みで位置58、出目1 | 勝者が設定される |
| 質問重複 | 3問の通常クイズを順に取得 | 3問の問題文がすべて異なる |
| 質問バンク | assetsの2ファイルを読み込む | 50問以上を取得できる |
| リザーブドインスタンス | 使用後にlossマスへ停止 | 損失が40ではなく20になる |
| Cost Explorer | 使用後に支払日を通過 | 支払いが50軽減される |
| DDoS と WAF | DDoSを使い、相手がWAF所持 | 相手クレジット不変、WAF消費 |
| Lambda | 使用後に通常マスへ停止 | 同じプレイヤーが次ターンを得る |
| リージョン障害とMulti-AZ | うわさを使い、相手がMulti-AZ所持 | 相手は休まず、Multi-AZ消費 |
