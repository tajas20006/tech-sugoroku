# DDD リファクタリング: 実装・テスト計画

## テスト戦略

| シナリオ | 入力 | 期待結果 |
| --- | --- | --- |
| 盤面境界 | 位置 3 / 15 / 未定義位置 | gain / payment / normal を返す |
| 支払日走査 | 14 から 16 へ移動 | 位置 15 の支払日だけを返す |
| クレジット不変条件 | 20 から 40 を失う | 0 になり負数にならない |
| 所持上限 | 3 個所持後に 4 個目を獲得 | 獲得を拒否し 3 個を維持 |
| RNG 注入 | 固定 `random.Random` を渡す | 集約が同じ RNG を使用する |
| リポジトリ差し替え | インメモリの問題リポジトリ | ファクトリーがその問題でゲームを生成する |
| Markdown アダプター | 既存 2 ファイル | 重複なしの 4 択問題を 50 件以上返す |
| 互換ファサード | `game` から旧 API を import | 旧 API が新実装を参照する |
| 依存方向 | domain の import を静的検査 | Flet / infrastructure / application に依存しない |
| 全ルール回帰 | 既存 19 テスト | すべて成功する |

## リスクと軽減策

- 公開クラスの移動による import 破壊: ルート互換ファサードと import 回帰テストで防ぐ。
- ランダム順序の変化: 同じ `random.Random` インスタンスを集約内の全ランダム処理で共有する。
- UI 演出の回帰: `TurnResult` の形を維持し、`tests/test_main.py` と import 検証を継続する。
- 循環依存: 値オブジェクトを `domain.model`、盤面を `domain.board`、集約を `domain.game` に一方向配置する。
